# Database migration policy

Migrations are an append-only compatibility boundary with the deployed
PostgreSQL schema. Never edit a SQL file after it has been applied and never
reuse a version number. Add the next unused numeric version instead.

`MANIFEST.json` is generated by `scripts/migration_manifest.py`. It records the
SQLx SHA-384 checksum for every migration and a SHA-256 over the ordered
inventory. The release gate refuses to run with a missing, duplicated, renamed,
or modified migration entry.

The history currently ends at version 22, which keeps a sample a minute of the
whole service (servers and players online, CPU, memory and TPS) for a day, for
the landing page's graphs. Version 21 records who added each whitelist entry,
gives server events an optional detail line and keeps the players a whitelist
recently turned away. Version 16 is the deployed CI
build-demand marker migration. Stable CI-build retention is version 17, the
fenced pull-request build queue is version 18 and the AI gateway (settings,
conversations, jobs, tool calls and the usage ledger) is version 19. Server
plugins (stored binaries, each server's plugin list and its load revision) are
version 20. The runtime-stats migration is version 15. This keeps the applied production chain
append-only and unambiguous while preserving every deployed checksum.
